# Pin every plugin EXACTLY and resolve them together in one `uv pip install`.
# Do not install these one-by-one or in separate RUN layers — that lets pip/uv
# resolve each plugin's dependencies in isolation, which is what silently
# breaks NetBox when a second or third plugin is added.
#
# Re-run `docker compose build --no-cache` after every change to this file.

# Pinned to NetBox 4.7.x. Most plugins declare an exact min/max NetBox version
# per release (netbox-bgp 0.20.x, netbox-inventory 2.7.x and
# netbox-floorplan-plugin 0.10.x are 4.7 only), and NetBox silently skips a
# plugin whose range does not match. After any bump, build the image and look
# for NetBox's "Unable to load plugin" warnings in the `docker compose build`
# output.
#
# netbox-secrets is NOT installed: its released 3.1.1 is capped at NetBox
# 4.6.99 and no 4.7-compatible release exists yet (the work is in an unmerged
# pull request). Add it back here, to configuration/plugins.py and to
# extensions/postgis-pathways/configuration/plugins.py once a release
# supports 4.7. Existing secrets stay in the database untouched; see
# docs/OPERATIONS.md.
#
# netbox-documents is wanted but NOT installed for the same reason: 0.8.5
# declares no max_version, so it loads on 4.7, but its Documents list page
# crashes ("'str' object has no attribute 'permissions_required'", NetBox
# 4.7 removed dict-style view actions) and its panel never renders with the
# default config. The fix is an unmerged pull request (#112). Add it back here
# and to both plugins.py files once a release works on 4.7.
#
# netbox-routing is NOT installed while netbox-bgp is: both define the GraphQL
# types CommunityType, CommunityListType and PrefixListType, and with both
# enabled NetBox exits at startup with DuplicatedTypeName. The image still
# BUILDS fine, so only a full start catches it (docs/OPERATIONS.md §3.3).
# The plan is to swap netbox-bgp for netbox-routing once netbox-routing has a
# stable release, and rebuild the sample dataset to match.
netbox-bgp==0.20.2

# Alpha-quality (pre-1.0). Pin exact versions, read the changelog before any
# bump, and back up the DB before running migrations after an upgrade.
# 0.6.0 derives fiber paths by analysis (FiberStrandPath) instead of storing
# traced paths, and its migration 0039 deletes all circuit path assignments;
# assign them again with POST /api/plugins/fms/fiber-circuits/<id>/assign/.
# Requires NetBox 4.5+.
netbox-fms==0.6.0

# Hardware inventory tracking. 2.7.x is NetBox 4.7 only; it migrates the
# asset contact field to contact assignments.
netbox-inventory==2.7.1

# TOTP two-factor login. Supports NetBox 4.0-4.99.
# IMPORTANT: otp_required defaults to True upstream, which locks every user
# out at next login until they register a device via `manage.py addtotp`.
# We override it to False below until you're ready to enforce it.
netbox-otp-plugin==1.3.6

# 0.10.x is NetBox 4.7 only (0.9.2 is the last release for 4.6).
netbox-floorplan-plugin==0.10.0

# Alpha software (data model/API may still change). 0.3.0 is min_version 4.7.0,
# no max. Optionally integrates with netbox-pathways (soft import, not required).
# 0.3.0 renames the C-band grid keys (dwdm_100ghz -> dwdm_c_100ghz, dwdm_50ghz
# -> dwdm_c_50ghz). Its migration 0012 rewrites the stored rows, but a client
# that still writes an old key is refused ("is not a valid choice"):
# netbox-sampledata needs 0.8.2 or later (0.8.1 cannot build on it). It also rejects invalid
# WDM cabling at save time and adds the optional setting max_trace_hops
# (default 20). Like 0.2.2, its channel and circuit trace tabs load D3 from
# d3js.org (netbox-fms from cdn.jsdelivr.net); Dockerfile-Plugins serves a
# pinned copy from NetBox's own static files instead, so they work offline.
netbox-wdm==0.3.0

# DNS zones, records, views and DNSSEC policies. The pip package is
# netbox-plugin-dns, the app label netbox_dns (the unrelated PyPI package
# "netbox-dns" was abandoned in 2023). The 1.7.x line is min_version 4.7.0
# (1.6.x is the line for 4.5/4.6). Pulls in dnspython.
netbox-plugin-dns==1.7.3

# Provider maintenance and outage events with a calendar and an iCal feed
# (/plugins/notices/ical/maintenances.ics). The app label is "notices".
# FullCalendar is bundled in the package, nothing loads from a CDN.
# min_version 4.5, no max. Pulls in icalendar.
netbox-notices==1.3.0

# Fills in the label of a cable that has none, from a Jinja template
# (default "#{{cable.pk}}"). Only release so far (Aug 2025), min 4.2, max
# 4.99.99. It writes the label with a queryset update after the cable is
# created, so that label is not in the change log and the API response to
# the create still shows it empty.
netbox-cable-labels==0.1.0

# Topology diagrams (vis-network, bundled). 5.0.0 is min_version 4.7.0 and
# fixes several XSS issues in 4.7.0. Breaking change in 5.0.0: the view
# respects object permissions, and saving node positions needs add/change
# permission on the coordinate models (coordinate, circuitcoordinate,
# powerpanelcoordinate, powerfeedcoordinate).
netbox-topology-views==5.0.0
